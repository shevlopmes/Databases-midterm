# Видео-демо на 1–2 минуты

Цель: показать свою БД в работе и объяснить ключевой компромисс. Ориентир —
1:40–1:55 с голосом. Ниже около 155 слов речи; оставляй небольшие паузы,
чтобы зритель успел прочитать результаты. Длительность зависит от темпа.

## Подготовка перед записью

Открой один терминал в папке проекта. Увеличь шрифт, оставь видимой только
нужную область терминала. Установки пакетов, отдельных окон сервера или
ручной выдачи токенов не требуется.

Для репетиции без пауз:

```powershell
cd C:\Users\Maxim\Documents\restaurant-db
python scripts/video_demo.py --auto
```

Для записи с остановками между шагами:

```powershell
python scripts/video_demo.py
```

Включи запись экрана и микрофона перед запуском. Прочитай речь для текущего
кадра и нажми Enter для следующего. После последнего шага оставь итоговый
результат на экране на пару секунд, затем останови запись.

Скрипт создаёт отдельный набор данных при каждом запуске внутри
`data/video-demo/`. Он не меняет существующие `demo-data`, `race-data` и токены.
Новые токены нужны только демонстратору: исходные секреты остаются в памяти,
на экран не выводятся, на диск записываются только verifiers.
После завершения сохраняются настоящий журнал и `report.json` с результатами.
Все запущенные демонстратором серверы завершаются; свои серверы останавливать
не нужно, используется свободный порт ОС.

Если проверка не пройдёт, скрипт остановится с ошибкой. Результаты не подставляются
из заготовки: используются существующий движок, HTTP API и реальные ответы.
Перезапусти демо после устранения причины; новый запуск получит свежие данные.

## Точность формулировок

- Здесь 20 одновременных HTTP-заявок от двух пользователей, а не 20 отдельных
  аккаунтов. Барьер синхронизирует старт клиентов; записи в БД последовательны.
- Публикация выполняется локально до старта HTTP. В текущей версии администрирование
  офлайн: CLI не может открыть каталог, пока им владеет сервер. Демо показывает
  атомарность публикации в движке, затем конкурентный доступ по HTTP.
- Проверяется аварийное завершение процесса. Эксперимент не проверяет отключение
  питания или поломку диска.
- Последний запрос действительно повторяется после запуска нового процесса;
  результаты берутся из журнала, а не из прежней памяти демонстратора.
- 20 заявок и 30-секундный клиентский таймаут — параметры локального показа,
  не заявленная производительность или ограничения самой БД.

Перед записью можно отдельно выполнить полный набор проверок:

```powershell
python -m unittest discover -q
```

Для ролика достаточно показанного сценария; полный прогон тестов занимает
отдельное время и не включён в текст речи.
